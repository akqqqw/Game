### Игровой цикл (as is)

1. `main.tsx` → `App` → `useEffect` → `hydrate()` (однократно, guard через `useRef`).
2. `hydrate()`: `loadGame()` из IndexedDB → расчёт офлайн-дохода = `min(простой, 8 ч) × energyPerSecond` → `hydrated: true`.
3. `setInterval(addPassiveEnergy, 1000)` — пассивный доход «тиками» по 1 секунде, только при `hydrated === true`.
4. Клик по дереву (Phaser) → `addEnergy()` → `+clickPower`, прогресс заданий, проверка достижений.
5. Любое действие → `persistState()` → **запись в IndexedDB на каждый клик** (fire-and-forget, `void`).

### Система сохранений (as is)

- Единственный слот: `evolution-isles` / `game-state` / `current`.
- Тип `PersistedGame` — **без поля версии схемы**; часть полей опциональна (`sunwellLevel?`, `stars?` …), в `hydrate()` подставляются дефолты «на месте».
- `savedAt: number` — используется только для расчёта офлайн-дохода.
- Ошибки IndexedDB нигде не перехватываются.

## 2. Проблемы: что мешает публикации

Приоритет = влияние на модерацию (требования Яндекс Игр от 22.09.2026).

### Критично (без этого игру не примут)

| 2 | Нет `LoadingAPI.ready()` (Game Ready) | 1.19.2 |

### Мелочи / рекомендации

- `transparent: true` у Phaser + фиксированный размер 760×560 при CSS `width/height: 100% !important` — работает, но хрупко; лучше отдать масштабирование `Scale.FIT` и не перебивать размеры `!important`.
- Иконка/название игры должны совпадать с черновиком (5.1.3), `favicon.svg` есть — проверить имена файлов без пробелов/кириллицы (1.22) — сейчас OK.
- Лимиты платформы: ≤ 100 МБ в разархивированном виде (1.21), `index.html` в корне архива (1.22). Текущая сборка — **1.58 МБ, 5 файлов** — с большим запасом.

## Этап 3 (раздел 3 ТЗ). Сохранения и облачный прогресс — выполнено

### Формат сохранения

| Файл | Назначение |
|---|---|
| `src/game/saveSchema.ts` | Версия схемы, миграции, нормализация любых входящих данных |
| `src/game/saveGame.ts` | IndexedDB: слоты `current` и `backup`, таймауты операций |
| `src/game/saveMerge.ts` | Стратегия разрешения конфликта «свежайший + резерв» |
| `src/platform/cloudSave.ts` | Облако SDK: debounce, лимиты, повтор, офлайн |
| `src/ui/CloudBar.tsx` + `.css` | Индикатор облака, уведомление, кнопка входа |
| `src/game/gameStore.ts` | Слияние при старте, синхронизация, уведомления |

- Актуальная версия схемы — **2**; сохранения без версии считаются версией 1 и мигрируют на чтении.
- Все данные проходят `normalizeSave()`: неизвестные существа/достижения отбрасываются, `NaN`/`Infinity`/отрицательные значения чинятся, мусор в облаке не может сломать игру.
- Проигравшая версия при конфликте уходит в слот `backup` — старые сохранения не теряются.

### Поведение

1. При старте читается локальное сохранение, затем (для авторизованного игрока) облачное, и применяется более свежее.
2. Пустое облачное сохранение никогда не перезатирает прогресс.
3. Сравнение идёт до первой записи локального прогресса, а после авторизации — относительно метки времени начала сессии (иначе локальная метка всегда выглядела бы свежее).
4. Запись в облако — с задержкой 5 с, не чаще 30 с, принудительно при уходе со страницы и сворачивании вкладки; лимит SDK (100 запросов / 5 минут) дополнительно ограничен собственным предохранителем 10 записей.
5. Нет сети — сохранение остаётся в очереди и уходит при восстановлении связи.
6. Гость играет полностью; прогресс пишется в IndexedDB, вход предлагается кнопкой с объяснением выгоды.

### Найденные и исправленные проблемы

- `hydrate()` обращался к облаку до инициализации SDK — теперь ждёт сессию не дольше 2 секунд и корректно дочитывает облако после её появления.
- После первых записей локальное сохранение всегда выглядело «свежее» облачного — сравнение ведётся по базовой метке сессии.
- Тест на пустые сохранения выявил выбор старого локального вместо свежайшего — исправлено.

### Как теперь начисляется доход

Раньше энергия добавлялась тиком `setInterval` по +1 секунде, а офлайн-доход считался отдельно при загрузке сохранения — при свёрнутой вкладке браузер троттлит таймеры, и суммы расходились.

Теперь правило одно: **доход начисляется за фактически прошедшее время ровно один раз**. Таймер только «подталкивает» начисление, а сумма считается как разница между текущим моментом и моментом последнего начисления:

- игра активна — раз в секунду начисляется прошедшая секунда;
- пауза (реклама, свёрнутая вкладка, меню) — таймер останавливается, при возобновлении пропущенное время начисляется одним разом;
- ограничение на разовый расчёт — 8 часов, как и у офлайн-дохода;
- дробный остаток меньше секунды не теряется (энергия всегда целая, время не «сгорает»).

### Что выяснилось про Phaser

Phaser сам останавливает игровой цикл при сворачивании вкладки и потере фокуса (`VisibilityHandler` + сброс дельты в `TimeStep`), поэтому эти случаи в игровом коде дублировать не нужно. Оставался необработанным случай платформенной паузы (реклама, окно покупки): окно при этом не скрывается, и сцена продолжала работать. Теперь сцена ставится на паузу по общим событиям паузы и снимается с паузы при возобновлении.

| `tests/platform/ads.test.ts`, `tests/platform/sdkMockAds.test.ts` | 22 теста |

### Принципы работы

- **Реклама выключена по умолчанию** (`enabled: false`): ни один вызов не уходит в SDK, пока флаг не включён. Баланс игры не изменён.
- **Показ только явным вызовом** из разрешённой точки: `showInterstitial()` / `showRewarded()`. Автопоказа нет ни по клику, ни по таймеру, ни при запуске.
- **Пейсинг полноэкранной рекламы**: запрет в первые минуты сессии, кулдаун 3 минуты, минимум 25 игровых действий между показами, запрет при скрытой вкладке и во время другого показа.
- **Пауза игры и звука** (п. 4.7): показ останавливает игровой цикл и звук через общую систему паузы; страховочный таймаут (60 с / 120 с) гарантированно вернёт управление, если колбэки SDK не придут.
- **Награда только за подтверждённый просмотр** (п. 4.5): `showRewarded()` возвращает `completed` исключительно после `onRewarded`; закрытие без просмотра — `skipped`, награда не выдаётся.
- **Все ветки обработки**: `completed`, `skipped`, `no-content` (нет рекламного контента), `error`, `unavailable` (нет SDK), `throttled` (пейсинг), `disabled`. Игра не ломается ни в одной из них.

### Рекомендуемые точки показа (подготовлены, не активированы)

Полноэкранная реклама — только в логических паузах: возврат на остров после раскрытия яйца, завершение покупки улучшения, переход между экранами. Вознаграждаемая — по кнопке игрока с явным указанием награды.

### Как проверить вручную (dev)

```js
window.__adsDebug.enable()            // включить рекламу
window.__adsDebug.showRewarded()      // мок-реклама с кнопками
window.__adsDebug.showInterstitial()  // мок полноэкранной рекламы
window.__adsDebug.state()             // статистика показов
```

Мок-реклама закрывается кнопками «Досмотреть и получить награду» и «Закрыть без награды» — видно, что награда выдаётся только в первом случае. Переменные адреса: `?mockAds=error` (ошибка показа) и `?mockAds=empty` (нет контента).

## Этап 6 (раздел 6 ТЗ). Интерфейс и платформы — выполнено

### Что сделано

**Каркас страницы.** `src/App.css`: `.game-shell` — flex-колонка высотой `100dvh` с `overflow: hidden` и `env(safe-area-inset-*)`; `.game-scroll` — единственная прокручиваемая область (экраны и панели); сцена вынесена над ней и не уезжает при скролле. Это закрывает требования «нет горизонтальной прокрутки» и «страница не скроллится» (п. 1.10.2).

**Сцена.** `.phaser-mount` — `width: 100%`, `aspect-ratio: 760 / 560`, по центру. На невысоких экранах (`max-height: 1000px`) ширина ограничивается `min(100%, 50dvh * 760/560)`, поэтому дерево и кнопки остаются в кадре без обрезки, а пропорции сцены сохраняются (п. 1.10.1, 1.10.4). На больших экранах сцена занимает всю ширину панели — на десктопе стала крупнее, чем была.

**Запреты браузера.** `src/index.css`: `html, body { overflow: hidden; overscroll-behavior: none }`, `user-select: none`, `-webkit-touch-callout: none`, `touch-action: manipulation` для кнопок и `touch-action: none` для канваса. Плюс `src/platform/platformGuards.ts`: `contextmenu`, `dragstart`/`selectstart`, `gesturestart`/`gesturechange`/`gestureend`, подавление двойного тапа. Поля ввода исключены из запретов — их можно выделять и вставлять в них текст.

**Мобильные разрешения.** `index.html`: `viewport-fit=cover`, `user-scalable=no`, `maximum-scale=1`, `theme-color`, apple-мета, `format-detection`. Кегль поднят до минимум 10px (были подписи 9px), тач-зоны навигации — не меньше 44px, в detail-экранах сетки перестроены.

**Полноэкранный режим.** `src/platform/fullscreen.ts`: `getFullscreenStatus()`, `requestFullscreen()`, `exitFullscreen()`, `toggleFullscreen()`, `isMobileDevice()`, `initMobileFullscreen()`. Своей кнопки в интерфейсе нет: у Яндекса есть своя кнопка в правом верхнем углу, дублировать её не нужно. Состояние читается из `ysdk.screen.fullscreen.status` (событие `fullscreenchange` при фуллскрине родительского фрейма не срабатывает), поддерживаются оба варианта API — флаг `status` и функции `isFullscreen()/request()/exit()`. На мобильных полный экран запрашивается первым касанием игрока, на десктопе ничего не меняется. Тип `YandexDeviceInfo` (`type` + `isMobile()/isDesktop()/isTablet()/isTV()`) добавлен в `sdkTypes.ts`.

**Шрифты.** Приложения шрифтов переведены на локальные пакеты `@fontsource/dm-sans` и `@fontsource/playfair-display`, внешний `@import` Google Fonts удалён — по правилам платформы внешние хосты недопустимы (п. 1.7). В DM Sans нет кириллицы, поэтому русский текст идёт системным шрифтом, а DM Sans отвечает за цифры и латиницу; заголовки — Playfair Display (кириллица есть). Внешний вид игры не менялся намеренно.

**Навигация.** В нижней панели 4 кнопки — «Остров», «Улучшения», «Существа», «Достижения». Дубль «Коллекция» убран (она живёт внутри экрана существ), нижняя панель больше не переполняется на узких экранах.
