### Игровой цикл (as is)

1. `main.tsx` → `App` → `useEffect` → `hydrate()` (однократно, guard через `useRef`).
2. `hydrate()`: `loadGame()` из IndexedDB → расчёт офлайн-дохода = `min(простой, 8 ч) × energyPerSecond` → `hydrated: true`.
3. `setInterval(addPassiveEnergy, 1000)` — пассивный доход «тиками» по 1 секунде, только при `hydrated === true`.
4. Клик по дереву (Phaser) → `addEnergy()` → `+clickPower`, прогресс заданий, проверка достижений.
5. Любое действие → `persistState()` → **запись в IndexedDB на каждый клик** (fire-and-forget, `void`).

### Система сохранений (as is)

- Единственный слот: `evolution-isles` / `game-state` / `current`.
- Тип `PersistedGame` — **без поля версии схемы**; часть полей опциональна (`sunwellLevel?`, `stars?` …), в `hydrate()` подставляются дефолты «на месте».
- `savedAt: number` — используется только для расчёта офлайн-дохода.
- Ошибки IndexedDB нигде не перехватываются.

## 2. Проблемы: что мешает публикации

Приоритет = влияние на модерацию (требования Яндекс Игр от 22.09.2026).

### Критично (без этого игру не примут)

| 2 | Нет `LoadingAPI.ready()` (Game Ready) | 1.19.2 |

### Мелочи / рекомендации

- `transparent: true` у Phaser + фиксированный размер 760×560 при CSS `width/height: 100% !important` — работает, но хрупко; лучше отдать масштабирование `Scale.FIT` и не перебивать размеры `!important`.
- Иконка/название игры должны совпадать с черновиком (5.1.3), `favicon.svg` есть — проверить имена файлов без пробелов/кириллицы (1.22) — сейчас OK.
- Лимиты платформы: ≤ 100 МБ в разархивированном виде (1.21), `index.html` в корне архива (1.22). Текущая сборка — **1.58 МБ, 5 файлов** — с большим запасом.

## Этап 3 (раздел 3 ТЗ). Сохранения и облачный прогресс — выполнено

### Формат сохранения

| Файл | Назначение |
|---|---|
| `src/game/saveSchema.ts` | Версия схемы, миграции, нормализация любых входящих данных |
| `src/game/saveGame.ts` | IndexedDB: слоты `current` и `backup`, таймауты операций |
| `src/game/saveMerge.ts` | Стратегия разрешения конфликта «свежайший + резерв» |
| `src/platform/cloudSave.ts` | Облако SDK: debounce, лимиты, повтор, офлайн |
| `src/ui/CloudBar.tsx` + `.css` | Индикатор облака, уведомление, кнопка входа |
| `src/game/gameStore.ts` | Слияние при старте, синхронизация, уведомления |

- Актуальная версия схемы на этом этапе — **2** (сейчас, после слияний и перебалансировки, — 4); сохранения без версии считаются версией 1 и мигрируют на чтении.
- Все данные проходят `normalizeSave()`: неизвестные существа/достижения отбрасываются, `NaN`/`Infinity`/отрицательные значения чинятся, мусор в облаке не может сломать игру.
- Проигравшая версия при конфликте уходит в слот `backup` — старые сохранения не теряются.

### Поведение

1. При старте читается локальное сохранение, затем (для авторизованного игрока) облачное, и применяется более свежее.
2. Пустое облачное сохранение никогда не перезатирает прогресс.
3. Сравнение идёт до первой записи локального прогресса, а после авторизации — относительно метки времени начала сессии (иначе локальная метка всегда выглядела бы свежее).
4. Запись в облако — с задержкой 5 с, не чаще 30 с, принудительно при уходе со страницы и сворачивании вкладки; лимит SDK (100 запросов / 5 минут) дополнительно ограничен собственным предохранителем 10 записей.
5. Нет сети — сохранение остаётся в очереди и уходит при восстановлении связи.
6. Гость играет полностью; прогресс пишется в IndexedDB, вход предлагается кнопкой с объяснением выгоды.

### Найденные и исправленные проблемы

- `hydrate()` обращался к облаку до инициализации SDK — теперь ждёт сессию не дольше 2 секунд и корректно дочитывает облако после её появления.
- После первых записей локальное сохранение всегда выглядело «свежее» облачного — сравнение ведётся по базовой метке сессии.
- Тест на пустые сохранения выявил выбор старого локального вместо свежайшего — исправлено.

| `src/App.tsx` | Убран `setInterval`: цикл дохода управляется движком; разблокировка звука на первом клике |

### Как теперь начисляется доход

Раньше энергия добавлялась тиком `setInterval` по +1 секунде, а офлайн-доход считался отдельно при загрузке сохранения — при свёрнутой вкладке браузер троттлит таймеры, и суммы расходились.

Теперь правило одно: **доход начисляется за фактически прошедшее время ровно один раз**. Таймер только «подталкивает» начисление, а сумма считается как разница между текущим моментом и моментом последнего начисления:

- игра активна — раз в секунду начисляется прошедшая секунда;
- пауза (реклама, свёрнутая вкладка, меню) — таймер останавливается, при возобновлении пропущенное время начисляется одним разом;
- ограничение на разовый расчёт — офлайн-лимит из баланса (сейчас 4 часа), как и у офлайн-дохода;
- дробный остаток меньше секунды не теряется (энергия всегда целая, время не «сгорает»).

### Что выяснилось про Phaser

Phaser сам останавливает игровой цикл при сворачивании вкладки и потере фокуса (`VisibilityHandler` + сброс дельты в `TimeStep`), поэтому эти случаи в игровом коде дублировать не нужно. Оставался необработанным случай платформенной паузы (реклама, окно покупки): окно при этом не скрывается, и сцена продолжала работать. Теперь сцена ставится на паузу по общим событиям паузы и снимается с паузы при возобновлении.

### Принципы работы

- **Реклама выключена по умолчанию** (`enabled: false`): ни один вызов не уходит в SDK, пока флаг не включён. Баланс игры не изменён.
- **Показ только явным вызовом** из разрешённой точки: `showInterstitial()` / `showRewarded()`. Автопоказа нет ни по клику, ни по таймеру, ни при запуске.
- **Пейсинг полноэкранной рекламы**: запрет в первые минуты сессии, кулдаун 3 минуты, минимум 25 игровых действий между показами, запрет при скрытой вкладке и во время другого показа.

- **Все ветки обработки**: `completed`, `skipped`, `no-content` (нет рекламного контента), `error`, `unavailable` (нет SDK), `throttled` (пейсинг), `disabled`. Игра не ломается ни в одной из них.

### Рекомендуемые точки показа (подготовлены, не активированы)

Полноэкранная реклама — только в логических паузах: возврат на остров после раскрытия яйца, завершение покупки улучшения, переход между экранами. Вознаграждаемая — по кнопке игрока с явным указанием награды.

Мок-реклама закрывается кнопками «Досмотреть и получить награду» и «Закрыть без награды» — видно, что награда выдаётся только в первом случае. Переменные адреса: `?mockAds=error` (ошибка показа) и `?mockAds=empty` (нет контента).

## Расстановка рекламы (после этапа 7)

Модуль рекламы был готов на этапе 5, но выключен. Теперь реклама включена и
расставлена по точкам показа.

### Как это устроено

Точки показа вынесены в отдельный модуль `src/platform/adPoints.ts` — это
единственное место, где описано, когда игра может показать полноэкранную
рекламу. Экраны вызывают `requestAdPoint('...')` после законченного действия,
а решение о показе принимает рекламный модуль с учётом пейсинга. Если убрать
эти вызовы или выключить рекламу, игра не меняется.

| Точка | Момент |
|---|---|
| `egg-hatched` | открылось яйцо |
| `fusion-done` | слияние завершилось новым существом |
| `upgrade-bought` | куплено улучшение |
| `habitat-upgraded` | жилище построено или улучшено |
| `screen-change` | переход на другой экран |

### Гарантии (п. 4.4 и 4.7 требований)

- Показ только после завершённого действия: если действие не прошло (не хватает
  энергии), точки не будет.
- Клики по дереву, наведение и прокрутка точками не являются — проверено тестом
  с отключённым пейсингом: 40 кликов не вызывают ни одного показа.
- На старте игры рекламы нет: показ возможен не раньше 2 минут сессии, 25
  действий игрока и с кулдауном 3 минуты.
- Одновременно запланирован только один показ; во время кулдауна новые не
  планируются вовсе (не остаётся «висящих» таймеров).
- Показ ставит игру и звук на паузу и гарантированно возвращает управление, в
  том числе при ошибке или отсутствии колбэков SDK.
- Вознаграждаемой рекламы в интерфейсе нет — только полноэкранная в паузах.

### Включение и проверка

- Реклама включается в `bootstrapPlatform()` — `configureAds({ enabled: true })`.
  Отключается одной строкой там же, игровая логика не затрагивается.
- В dev доступен ускоренный режим `?adsFast=1`: уменьшенные задержка, кулдаун и
  минимум действий — мок-реклама появляется после нескольких действий.
- `window.__adsDebug` умеет `state()`, `canShowInterstitial()`,
  `showInterstitial()`, `disable()`.

## Звук (после расстановки рекламы)

Раньше звуковой модуль был готов, но игра работала беззвучно: звуковых файлов
в проекте не было. Теперь звук включён.

### Почему синтез, а не файлы

Звуки рассчитываются кодом (`src/platform/sounds.ts`) в аудиобуферы при
создании аудиоконтекста. Это снимает ограничения сразу по нескольким пунктам:

- **п. 1.7** — нет внешних хостов: скачивать звуки со сторонних хранилищ нельзя,
  а своих файлов в проекте не было;
- **лицензии** — синтезированный звук не требует прав на чужой контент;
- **вес архива** — звуки не занимают ни одного байта (архив остался 19 файлов);
- **надёжность** — нечего загружать: звук работает при плохой связи и после
  сборки, без «битых» путей к ассетам.

### Что звучит

Клик по дереву (с вариацией тона), покупка улучшения, вылупление яйца, слияние,
мутация, постройка жилища, достижение и переход между экранами.

### Выполнение требований

| Требование | Как выполнено |
|---|---|
| п. 1.3 — звук останавливается при потере фокуса | подписка на события паузы платформенного слоя |
| п. 4.7 — звук на паузе во время рекламы | то же событие `ad`, звук обрывается |
| п. 6.2 (рекоменд.) — возможность отключения звука | кнопка 🔊 в верхней панели, настройка запоминается |
| п. 1.8 — удобство нажатия | тач-зона кнопки 44×44 px |

## 3D-модели существ

Карточка существа получила витрину: вращающаяся 3D-модель вместо статичного
эмодзи. Своих моделей в проекте пока нет, поэтому существа рисуются
**процедурно** — из примитивов, по стихии и редкости (`src/game/creatureModels.ts`
собирает детерминированный рецепт, `src/game/creatureMesh.ts` — меш). Рецепт не
меняется между открытиями, поэтому существо всегда выглядит одинаково.

### Почему three.js и почему лениво

Phaser 4 не умеет 3D, поэтому витрина — отдельный слой. Three.js весит 157 КБ
в сжатом виде, и в стартовой загрузке ему не место:

| Слой | Вес (gzip) | Когда грузится |
|---|---|---|
| Основной бандл | 454 КБ | сразу |
| Чанк витрины (`creatureViewer`) | 159 КБ | при первом открытии карточки существа |

В собранном архиве чанк лежит отдельным файлом (`assets/creatureViewer-*.js`) и
подключается относительным путём — требование п. 1.7 (никаких абсолютных
адресов) выполняется. Архив вырос с 698 КБ до 856 КБ (лимит 100 МБ).

### Запасные варианты

| Ситуация | Что видит игрок |
|---|---|
| Нет WebGL (старый браузер, отключена графика) | эмодзи, как раньше |
| Модель не загрузилась или повреждена | процедурную модель |
| Первый кадр не нарисовался (драйвер, шейдеры) | эмодзи — витрина освобождает ресурсы |
| Рендер сломался на ходу | эмодзи (витрина сообщает интерфейсу об ошибке) |
| Открыта реклама, вкладка свёрнута, потерян фокус | рендер полностью остановлен (п. 1.3, 4.7) |
| Системная настройка «уменьшить движение» | модель статична, без вращения |

При закрытии карточки освобождаются геометрии, материалы и WebGL-контекст:
окно контекстов в браузере ограничено, утечка закрыла бы игру после десятка
просмотров.

### Анимация: игра или модель

Пока своих анимаций нет, существо оживляет витрина: вращение (рассмотреть со
всех сторон), покачивание и дыхание — с индивидуальными параметрами из рецепта
(`spin`, `float`, `breath`). Когда в модели появится idle-анимация, она
включается автоматически: клип с `idle` в названии приоритетнее прочих,
зацикливается, а покачивание и дыхание отключаются, чтобы не спорить с ним.
Выбор клипа и микшер вынесены в `pickAnimationClip` / `createModelAnimator` —
их поведение проверяется отдельно, без WebGL.

### Модели из Blender

Пайплайн готов: файл `public/models/creatures/<id>.glb` плюс id в списке
`creatureModelFiles` — и модель занимает место процедурной. Загрузка через
`GLTFLoader`, масштаб и центрирование нормализуются игрой, поэтому требования к
экспорту минимальны. Полная спецификация (имена файлов, полигонаж, материалы,
текстуры, порядок работы) — в [`docs/creature-models.md`](creature-models.md).
